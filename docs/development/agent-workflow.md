# Agent Workflow

This public branch keeps documentation practical and source-aligned. Prefer
small, verifiable changes and update docs when behavior, commands, or public
asset expectations change.

## Responsibilities

- Read `AGENTS.md` and the narrow docs relevant to the task.
- Preserve the public/private boundary for assets and documentation.
- Keep code changes scoped to the requested behavior.
- Run focused validation first, then broaden when shared runtime behavior is
  affected.
- Report commands run and any checks that could not be completed.

## Public Documentation Rules

- Do not add private roadmaps, commercial plans, status ledgers, or live
  infrastructure details.
- Do not document private content import or curation workflows.
- Do not add provider keys, OAuth secrets, account data, or private deployment
  identifiers.
- Keep module-local README files focused on how to use that module in this
  public branch.

## Handoff Format

For substantial work, report:

- files or areas changed
- behavior changed
- validation run
- remaining risks or skipped checks
